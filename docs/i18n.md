# Übersetzung (i18n)

Stand: 2026-09-23 · Branch: `feat/workbench-layout-design`

Jeder Text, den die Oberfläche zeigt, ist ein Schlüssel. Die Wörter dazu liegen
in dem Paket, das sie zeigt: `src/i18n/<sprache>.json`, eine Datei je Sprache.
Ein Paket wird mit seinen Texten ausgeliefert und braucht dafür kein anderes.
Welche Sprache gilt, entscheidet die Person am Umschalter im Kopf der App; ohne
Wahl gilt die Sprache des Browsers, und wo ein Paket die nicht hat, Englisch.

---

## 1. Die Teile

| Teil | Wo | Aufgabe |
|---|---|---|
| i18next | `packages/lib/i18next` | Richtet i18next ein (Startsprache, `fallbackLng: 'en'`, `defaultNS: 'common'`), meldet es als Dienst `I18next` an, setzt `<html lang>` und warnt auf `localhost` vor fehlenden Schlüsseln. Für Code außerhalb einer Komponente: `translate(key)` und `currentLanguage()`. |
| Texte eines Pakets | `<paket>/src/i18n/` | `en.json`, `de.json`, … und das daraus erzeugte `index.ts`: eine Komponente, die die Texte als Dienst `Translations` anbietet. `src/index.ts` exportiert sie, das Manifest nennt Namensraum und Sprachen (Capability `tsm.i18n`). |
| `TranslationTracker` | `packages/lib/i18next` | Sammelt jeden Dienst `Translations` ein (`@injectAll`) und gibt die Texte an i18next; stoppt ein Bundle, nimmt er sie wieder heraus. Es gibt keine Liste der Pakete. |
| `useTranslation(ns)` | `ui.vue.composables` | Reaktives `t`: rendert neu, wenn ein Paket ankommt oder die Sprache wechselt. |
| `useLanguage()` | `ui.vue.composables` | Liste der Sprachen, die i18next tatsächlich hat, und die Wahl (in `localStorage` unter `daanse.board.language`). |
| `useFormat()` | `ui.vue.composables` | Zahlen und Daten über `Intl` in der aktuellen Sprache - nie mehr fest `'de-DE'`. |
| `useText()` | `ui.vue.controls` | Dasselbe für die paar Wörter der Controls, ohne Abhängigkeit auf die Composables (Namensraum `controls`). |
| Modell-Labels | `ui.vue.uimodel` | `label="ns:Key"` in einer `.xmi` wird übersetzt, ebenso ein `optionLabel`, das einen Schlüssel liefert. |
| Prüfung | `scripts/i18n.mjs` | `sync` erzeugt `src/i18n/index.ts`, den Export und die Capability im Manifest, `check` prüft Schlüssel und Zuständigkeit (siehe 5.). |

## 2. Namensräume

Ein Namensraum je Paket, und jedes Paket hat genau einen. Er steht im
Manifest:

```json
{ "namespace": "tsm.i18n", "attributes": { "namespace": "chart", "languages": ["de", "en"] } }
```

- `common` - Wörter, die überall gleich sind (`Action.cancel`, `Action.save`, …).
  Gehört `ui.vue.composables`, das `useTranslation` liefert; wer die Wörter
  benutzt, hängt ohnehin davon ab.
- `shell`, `controls`, `uimodel`, `eventmanager`, `persistence`, `xmla`, `kpi`, `monaco`
- je Widget einer, in camelCase nach dem Pfad unter `widget/`:
  `chart`, `textPlain`, `textRich`, `svgBase`, `svgRepeat`, `tableData`,
  `tableKpi`, `tablePivot`, `xmlaFilters`, …
- alle anderen in camelCase nach dem Pfad unter `ui/vue/`:
  `datasourceCsv`, `connectionXmla`, `composerChart`, `layoutsGrid`,
  `pluginsGeojsonRenderer`, `variableComponents`, …

Ein Paket liest seinen eigenen Namensraum und die der Pakete, von denen es
abhängt (`dependencies` im Manifest) - sonst zeigte es, allein ausgeliefert,
nur Schlüssel. Braucht es ein Wort, das ein anderes Paket auch hat, bekommt
es eine eigene Kopie.

Innerhalb eines Namensraums gruppieren die Schlüssel nach Komponente oder
Formular: `Settings.*`, `Widget.*`, `Form.*` (Labels aus `ui.xmi`),
`Options.*` (Optionen aus `optionLabel`). Der Name eines Widgets in der Palette
ist immer `<ns>:Widget.name`.

## 3. Einen Text hinzufügen

In einer Komponente:

```vue
<script setup lang="ts">
import { useTranslation } from 'org.eclipse.daanse.board.app.ui.vue.composables'
const { t } = useTranslation('chart')
</script>

<template>
  <DButton>{{ t('Reference.addLine') }}</DButton>
  <DInput :label="t('Reference.label')" />
  <p>{{ t('Storage.pages', { count: 3 }) }}</p>
</template>
```

Dann den Schlüssel in **jede** Sprache des Pakets schreiben:
`packages/ui/vue/widget/chart/src/i18n/en.json` und `…/de.json`.

Regeln, die sich bewährt haben:

- **Ganze Sätze als ein Schlüssel**, Werte über Interpolation (`{{name}}`),
  nicht aus Stücken zusammengesetzt - die Wortstellung ist je Sprache anders.
- **Mehrzahl über i18next**: `key_one` / `key_other`, aufgerufen mit `count`.
- **Listen von Optionen als `computed`**, damit sie beim Sprachwechsel neu
  gebaut werden; ein Array auf Modulebene wird nur einmal übersetzt.
- **Nichts vergleichen, was übersetzt ist.** Wer einen Abschnitt oder eine
  Option wiederfinden muss, nimmt eine Kennung (`data-section-id`, `value`),
  nicht den angezeigten Text.
- **Gespeicherte Daten bleiben Daten.** Ein Name, den jemand vergeben hat, wird
  nicht übersetzt; nur was die App vorschlägt (`Neue Seite`), wird beim
  Anlegen in der aktuellen Sprache geschrieben.
- Eine Undo-Beschriftung (`history.record(label, …)`) ist ein Schlüssel; der
  Kopf der App übersetzt sie beim Anzeigen.

Außerhalb einer Komponente, etwa in einer Registrierung: den voll
qualifizierten Schlüssel als Wert ablegen (`nameKey: 'chart:Widget.name'`,
`label: 'eventmanager:Nav.label'`) und dort übersetzen, wo er gezeigt wird.

## 4. Formulare aus `.xmi`

```xml
<fields xsi:type="uimodel:InputWidget" name="title"
    feature="…#//WrapperSettings/title" label="wrapper:Form.title"/>

<fields xsi:type="uimodel:SelectWidget" name="fit" …>
  <values>cover</values>
  <optionLabel language="JS" body="({ cover: 'video:Options.fit.cover' })[option] ?? option"/>
</fields>
```

Ein Label der Form `ns:Key` wird beim Laden gemerkt und bei jedem
Sprachwechsel neu ins Modell geschrieben (`translateLabels.ts`); ein Label ohne
Doppelpunkt bleibt, wie es ist. Ein `optionLabel`, das einen Schlüssel liefert,
übersetzt `SettingsFieldWidget`.

## 5. Prüfen

```bash
yarn i18n:sync    # nach einer neuen oder entfernten Sprachdatei, einem neuen Paket
yarn i18n:check   # läuft auch in der CI
```

`check` schlägt fehl, wenn

- ein Schlüssel benutzt wird, den der genannte Namensraum nicht hat,
- ein Paket einen Schlüssel hat, den nichts benutzt,
- die Sprachen eines Pakets nicht dieselben Schlüssel haben, oder `en.json` fehlt,
- ein Text leer ist,
- zwei Pakete denselben Namensraum beanspruchen,
- ein Paket einen Namensraum liest, der weder seiner noch der eines Pakets
  ist, von dem es abhängt,
- `src/i18n/index.ts`, der Export in `src/index.ts` oder das Manifest veraltet sind.

Schlüssel, die erst zur Laufzeit zusammengesetzt werden
(`` t(`Settings.units.${unit}`) ``), sieht das Skript nicht; die Datei nennt
sie in einem Kommentar: `// i18n-keys: timeline:Settings.units.*`.

Dazu warnt ESLint (`vue/no-bare-strings-in-template`) vor Wörtern, die direkt
im Template stehen. Zeichen, Einheiten und Namen wie `URL` sind erlaubt.

## 6. Texte in einem neuen Paket

1. `src/i18n/en.json` anlegen (und je weitere Sprache eine Datei).
2. Ins Manifest die Capability eintragen:
   `{ "namespace": "tsm.i18n", "attributes": { "namespace": "<ns>" } }`.
3. `yarn i18n:sync` - erzeugt `src/i18n/index.ts`, exportiert die Komponente
   aus `src/index.ts`, ergänzt die Sprachen im Manifest und
   `@eclipse-daanse/tsm` in `package.json`.

Eine Test-Umgebung, die Pakete ohne den Loader lädt, gibt die Texte von Hand
an i18next: `addTranslations(new ChartTranslations())` aus `lib.i18next`
(siehe `packages/ui/vue/test/widget/map/src/main.ts`).

## 7. Eine Sprache hinzufügen

In jedem Paket, das die Sprache sprechen soll, `src/i18n/<tag>.json` neben
`en.json` legen und übersetzen, dann `yarn i18n:sync` und `yarn i18n:check`.
Ein Paket ohne die Datei zeigt in dieser Sprache Englisch.

Der Umschalter zeigt die Sprache, sobald ein Paket mit Texten in ihr geladen
ist - es gibt keine Liste, die man pflegen müsste.

## 8. Was nicht übersetzt wird

- Beschreibungen und Feldnamen, die aus den `.ecore`-Modellen kommen
  (Verbindungs- und Datenquellen-Typen im Anlegen-Dialog) - sie stehen im
  Modell, nicht in der Oberfläche.
- Typkennungen (`rest`, `xmla`, …), Protokoll- und Produktnamen.
- Was Benutzer selbst benennen: Boards, Seiten, Verbindungen, Stile.
- Log- und Konsolenausgaben.
